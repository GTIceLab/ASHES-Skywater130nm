# ASHES SkyWater 130 nm

Sky130 analog cell sources, GDS libraries, shared ASHES library generation, and a reproducible
ASHES-to-OpenROAD example from the Georgia Tech ICE Lab. This repository is the
Sky130-specific companion to [ASHES](https://github.com/GTIceLab/ashes), intended
as a public reference for its library interfaces and physical-design workflow.

The repository supplies circuit/library content; ASHES is installed separately.
The public [SkyWater PDK](https://github.com/google/skywater-pdk) supplies the
process models and technology tooling needed for circuit simulation and editing.
It is not bundled here as a complete PDK installation.

## Quick start

Use **Linux**, **WSL2 with Ubuntu**, or a **Linux VM**. On Windows, run the
commands in the WSL terminal. OpenROAD GUI use requires a display such as WSLg.
Install Python 3.12 or newer, ASHES, OpenROAD, and KLayout in that environment.

```bash
git clone https://github.com/GTIceLab/ashes.git
git -C ashes switch main
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e ./ashes

git clone https://github.com/GTIceLab/ASHES-Skywater130nm.git
cd ASHES-Skywater130nm/Tools/lib
ashes cells generate --cells IndirectVMM_4x2 TA_FGbias_1x2 \
  --process-node 130 --foundry sky --process-coordinates xy
cd ../run_syn/Sky130_Trial
ashes asic Trail.py
openroad -threads 8 -exit -log openroad.log openroad/Trail/main.tcl
```

See [setup](docs/setup.md) to install OpenROAD/KLayout and select the verified
ASHES revision. No local usernames or fixed checkout paths are required.
The documented branch uses `ashes_fg.asic.asic_compile` and does not accept
`process_coordinates` in synthesis settings. Other ASHES branches can have a
different API; pin the documented revision when reproducing the example.

The example imports `Tools/lib/cell_def/cells.py` directly. Generation of
OpenROAD inputs and execution of OpenROAD are separate commands. Run ASHES from
the example directory so its relative library paths resolve correctly.

## Library and example status

The included trial is a 4 x 4 `IndirectVMM_4x2` array and a 4 x 1
`TA_FGbias_1x2` array in a 150 x 150 micron die. Island origins are (20, 42)
and (100, 42) microns. Python placement values are in nanometers; PD settings
use microns. The source circuit's wiring is retained.

All 19 raw prepared GDS files are included. The shared generator accepts 10 interfaces individually and reports explicit
errors for nine others (sparse/conflicting labels or hierarchical annotations).
No batch command silently skips a requested cell. See the recorded individual
generation results for details. The checked-in `cells.py` contains only the two cells used by the trial,
so this unrelated error does not prevent importing the example library.

The earlier complete OpenROAD/KLayout run produced a GDS with 231 remaining
DRC violations. Synthesis, routing, and cell-level verification are different checks. A generated
GDS is not a claim of DRC/LVS, power integrity, or fabrication readiness. See
[validation status](docs/validation.md) for the checks actually performed and
[known source limitations](docs/source-status.md) for legacy schematic references.

## Working with the cell sources

Install the public Sky130 PDK, Xschem, Magic, and ngspice to edit and simulate the
sources. Configure each tool for your PDK installation. Standard PDK symbols and
models are external dependencies; this repository does not replace them.
The project `xschemrc` loads the installed PDK and repository symbols; use
`bash scripts/open_xschem.sh` as described in the [Xschem guide](docs/xschem.md).
Included symbol references use stable repo-root paths. Some historical sources reference absent or ambiguous symbols; they
are documented rather than presented as verified standalone designs.

For KLayout, use the `.lyp` file for display and `sky130_EDA.layermap` for routed
DEF-to-GDS conversion. They are not interchangeable.

## Validate the checked-in library

With the ASHES environment active, run from the repository root:

```bash
python scripts/validate.py
```

This checks source syntax, JSON, and the two trial classes against GDS pin
names and widths. It does not replace routing, DRC, or LVS.
